# LEGE planning and delegation

Use one brief planner before project execution. It must cover implementation, verification, coordination, and likely waiting: Plan ID; project/task; scope; success criteria/evidence; model choices; provisional usage/credit and elapsed-hour ranges; actual-hours-saved assumption; milestone caps; 75% reforecast; stop/replan conditions; and opening quota snapshot when available. Preserve its initial estimate and append versioned changes with their reasons.

Reuse an applicable plan and its remaining budget before every task. Exempt extra planning/delegation when planning, delegation, additional governance review and immediate cloud logging would cost at least as much as direct execution; required task verification still applies. Use local collection and defer cloud synchronization to the next worthwhile batch. Compare expected total consumption including inherited context, retries and parent coordination, not just the worker's per-token price. A brief deterministic overhead decision is sufficient. Estimates are provisional, not technically enforced. Never infer fixed relationships among quota percentage, tokens, credits, or billing.

Use available models by LEGE: choose from models actually available in the session using verified cost information. More expensive models need a documented difficult/high-risk reason. A parent cannot be model-switched by this skill. Delegate only independent bounded work that can proceed alongside useful local work. Spawn with explicit suitable model and minimal brief, require bounded evidence, prohibit recursive planning/delegation, and account separately for coordination, child work, and waiting. Fresh-context agents still receive system/tool/skill context: estimate actual repeated request input, not brief length alone. Check the planner's arithmetic and acceptance criteria; escalate a failing cheap planner once rather than repeating ineffective attempts. Do not manufacture parallelism for a serial job; recommend a cheaper root session if material cost cannot otherwise be reduced.

At 75% of planned usage or elapsed hours, reforecast. At the cap, preserve an inspectable partial result and stop; request more budget only if required to finish. Record user acceptance separately from technical checks. For creative work, distinguish technical validation from the owner accepting the result.

Use the existing `Project budgets` tab. Its columns A:V are Project, Deliverable, Acceptance check, Credits low, Credits ceiling, Hours low, Hours ceiling, Actual credits, Actual active hours, Planner, Executor, Status, Owner result, Evidence / stop rule, Plan ID, Estimate basis, Opening quota used, Closing quota used, Input budget low, Input budget high, Output budget low, Output budget high. Put per-model cached subsets, waiting assumptions and milestone caps in Estimate basis. Never put hours saved into Actual active hours.

Before execution, append a unique Plan ID and the full completion forecast (including planning already consumed); retain the original numeric estimate. A changed scope or ceiling gets a new revision row linked to the prior Plan ID, not an overwritten estimate. Reconcile every task to one plan and reserve its portion of the shared remaining budget; simultaneous tasks cannot each consume the full project cap. Measure root and child usage by assigned turn/response IDs or recorded counter deltas, excluding unrelated historical project activity. For actual active hours, union execution intervals across agents, excluding pauses between sessions; report unmeasured time as unavailable. Quota snapshots are account-wide and may contain concurrent activity. A reset invalidates a simple before/after subtraction.

Mark technical delivery separately from owner acceptance. Failed/no-value attempts remain costs of the project. Preserve user reviews and dated rates.
